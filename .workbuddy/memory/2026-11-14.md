- 环境：无 `gh`、无 credential helper，但 Git Credential Manager 缓存了 PAT（`git credential fill` 返回 `gho_…`）；GitHub 访问须走 18080 代理（env 内部代理 64761 会让 git schannel TLS 失败，R018）。
- 发版用 GitHub REST API + PAT：POST `/repos/csazhu/node/releases`（`make_latest` 传字符串 `"true"`，R020），`upload_url` 模板剥 `{?name,label}` 后拼 `?name=dota-stats.exe` 走 `uploads.github.com` 上传二进制；curl 走 18080 代理。
- **坑**：`/tmp` 在 Git Bash(msys) 与 Windows Python 间解析不一致，导致 curl 读不到 python 写的 payload 文件、且有旧残留文件干扰；发版脚本改为「payload 用 shell 变量、响应直接管道解析」，不落地临时文件。
- 结果：Release `v1.2.0` 创建成功（id 445119421，html_url 指向 v1.2.0），exe 已上传（9,933,262 字节，state=uploaded）；`git push origin main`（走 18080）成功 `c46b007..2a57b10`；远程 `version.json`=1.2.0、`/releases/latest/download/dota-stats.exe` 匿名 200 验证通过。
- **tag 对齐**：创建 Release 时 GitHub 基于当时旧 main tip 自动打了 tag `v1.2.0`（指向旧 `c46b007`），需手动 `git tag -f v1.2.0 2a57b10` + `git push --force-with-lease=refs/tags/v1.2.0:<旧sha>` 对齐到新提交（个人仓库、tag 刚建、目标仍为祖先，--force-with-lease 显式基准，安全）；复验 tag → `2a57b10` ✓。
- 注意：`--force-with-lease` 无本地追踪 ref 时会 stale info 拒绝；用显式 `=ref:期望sha` 基准即可。
