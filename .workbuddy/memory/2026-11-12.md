## 取数架构：各接口独立线程并行 + 独立比对更新（commit 5944628）

- 需求：用户要求「这几个接口和版本号都走多线程分别获取，各自独立比对、独立更新，不做单线程」。
- 改动：
  - `DataFetcher` 拆出 `fetch_ranking`/`fetch_info`/`fetch_recent`（各独立网络请求，失败由调用方容错）、`derive_rows_days(recent)`、`build_profile(ranking, info)`；`collect()` 改为串行调用这些助手并保留 token 失败抛 RuntimeError、单接口失败记 warnings/failed 的兼容行为（test_app.py 仍绿）。
  - `_begin_fetch` 不再单线程 `collect`：为 排行榜/会员赛季资料/近期战绩 各起一个 daemon 线程并行请求（版本号走已有的 `_maybe_refresh_version` 独立线程）。各线程把 `(key,res,err,label)` 放入 `_results`；`_poll_results` 按 key 分发到 `_on_data_ranking/info/recent`，各自只比对自己那份数据（`_last_rank` / `_last_info_fields` / `self.rows+self.days`），变了才重绘对应区块；`_finish_round` 三接口收齐后统一收尾（状态栏/时间戳/ctrl.finished）。
  - `render()` 重构为复用同一套 `_on_data_*` / `_apply_recent_data` 独立比对逻辑（失败接口保留旧内容），测试与手动全量刷新仍走 `render`。
- 验证：81 项单测全绿（含改造后的 `test_auto_refresh_loops`：mock 三 fetch、3 次/轮、验证连续≥3轮与「更新于」时间戳）。AGENTS.md 新增 R033（取数架构）。

- 验证：85 项单测全绿（两次）；`tests/test_version.py` 新增 `test_changelog_closes_on_click_of_non_focusable_widget`（模拟焦点仍停留弹窗、点击不抢焦点组件也应关）。AGENTS.md 新增 R037。
